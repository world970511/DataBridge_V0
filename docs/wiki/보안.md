# 보안

## 인증 시스템

### 로그인

- 모든 페이지 접근 시 로그인 필수
- 서버 사이드 세션 관리 (Streamlit session_state)
- 비밀번호: salt + SHA-256 해시 저장

### 역할 기반 접근 제어

| 역할 | 접근 가능 페이지 |
|---|---|
| **admin** (관리자) | 💬 채팅, 📁 데이터 관리, ✅ 승인 관리, ⚙️ 설정 |
| **user** (일반 사용자) | 💬 채팅, 📁 데이터 관리, 📋 내 요청 현황 |

- 초기 관리자 계정: `admin` / `.env`의 `ADMIN_PASSWORD`
- 관리자가 일반 사용자 계정을 추가/관리 가능

## SQL 안전장치

### 4단계 위험도 분류

`approval/sql_classifier.py`에서 SQL 문의 첫 키워드를 분석하여 분류합니다.

| 카테고리 | SQL 키워드 | 동작 |
|---|---|---|
| **SAFE** | `SELECT` | 즉시 실행 (읽기 전용) |
| **AUTO_ALLOWED** | `CREATE`, `INSERT`, `UPDATE` | 자동 실행 허용 (마트 생성 등) |
| **NEEDS_APPROVAL** | `DROP`, `DELETE`, `TRUNCATE`, `ALTER` | 관리자 승인 필요 |
| **FORBIDDEN** | `GRANT`, `REVOKE`, `EXECUTE`, `COPY`, `LOAD` | 항상 차단 |

### 추가 안전장치

- **SQL 주석 차단**: `--`, `/* */` 포함 시 FORBIDDEN (인젝션 방지)
- **다중 문장 차단**: 세미콜론으로 구분된 다중 SQL 차단
- **마트 네이밍**: 마트 테이블은 반드시 `mart_` 접두사 필요
- **분류 불가**: 어떤 카테고리에도 해당하지 않으면 FORBIDDEN (안전 우선)

## 승인 레이어 (Human-in-the-Loop)

### SQL 승인 워크플로우

```
에이전트가 SQL 생성
    │
    ▼
sql_classifier.py로 분류
    │
    ├─ SAFE (SELECT) ────────▶ 즉시 실행 → 결과 반환
    ├─ AUTO_ALLOWED ─────────▶ 자동 실행 (마트 생성 시 승인 UI 표시)
    ├─ NEEDS_APPROVAL ───────▶ approval_requests 테이블에 등록
    │                              │
    │                              ▼
    │                         관리자가 승인 관리 페이지에서 확인
    │                              │
    │                              ├─ [승인 & 실행] → SQL 실행 → 결과 기록
    │                              ├─ [승인만] → 상태만 approved로 변경
    │                              └─ [거부] → 사유 기록
    │
    └─ FORBIDDEN ────────────▶ 차단 (실행 불가)
```

### 리소스 삭제 승인 워크플로우

```
사용자가 데이터 관리 페이지에서 [삭제 요청] 클릭
    │
    ▼
approval_requests에 등록 (request_type='delete_resource')
  metadata: {resource_type, resource_name, source_file, details}
    │
    ▼
관리자가 승인 관리 페이지에서 확인
    │
    ├─ [승인 & 삭제] → 리소스 유형별 삭제 실행:
    │     ├─ 테이블: DROP TABLE + catalog 제거
    │     ├─ 문서: ChromaDB 청크 삭제 + catalog 제거
    │     └─ 이미지: ChromaDB 임베딩 삭제 + 썸네일 삭제 + catalog 제거
    │     + 원본 소스 파일 삭제 (존재 시)
    │
    └─ [거부] → 사유 기록
```

> ⚠️ 예외: 공유 폴더에서 파일을 직접 삭제하면 `watcher/cleanup.py`가 즉시 정리합니다 (승인 불필요).

## 감사 로그

`audit_log` 테이블에 모든 주요 이벤트가 기록됩니다.

### 기록되는 이벤트

| action_type | 설명 |
|---|---|
| `query` | 채팅 질의 (질의문 + 생성된 SQL) |
| `approval_request` | 승인 요청 생성 |
| `approval_granted` | 승인 완료 |
| `approval_denied` | 승인 거부 |
| `execution` | SQL 실행 완료 (결과 요약 포함) |
| `error` | 오류 발생 |

### 기록 내용

- **누가**: user_id
- **언제**: created_at (타임스탬프)
- **무슨 질의를**: query_text
- **어떤 SQL을 생성했고**: sql_generated
- **결과는 어땠는지**: result_summary, status
- **추가 정보**: metadata (JSONB)

## 에이전트 권한 요약

```
에이전트가 할 수 있는 것               에이전트가 할 수 없는 것
─────────────────────             ─────────────────────
✅ SELECT (모든 테이블)               ❌ DROP / TRUNCATE
✅ CREATE TABLE mart_*              ❌ DELETE / UPDATE (원본)
✅ INSERT INTO mart_*               ❌ ALTER TABLE
✅ 문서 벡터 검색                     ❌ 원본 테이블에 쓰기
✅ 이미지 유사 검색                   ❌ 리소스 직접 삭제
✅ 이미지 그룹핑/중복 탐지             ❌ 승인 없이 실행
✅ 배치 등록 (승인 후)                ❌ GRANT / REVOKE
```
