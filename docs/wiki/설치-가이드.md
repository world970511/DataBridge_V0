# 설치 가이드

## 준비물

| 항목 | 조건 | 비고 |
|---|---|---|
| **서버** | Linux (Ubuntu 22.04+) 또는 Windows | 사내 여유 서버 1대 |
| **RAM** | 16 GB 이상 | 이미지 처리(DINOv2) 사용 시 32 GB 권장 |
| **디스크** | 50 GB 이상 | 데이터 규모에 따라 |
| **GPU** | 없어도 됩니다 | 있으면 LLM 응답 + 이미지 처리가 빨라짐 |
| **Docker** | Docker Compose v2.20+ | |
| **Ollama** | v0.3 이상 | 폐쇄망인 경우. 상용 모델 사용 시 불필요 |
| **네트워크** | 사내망 접근 가능 | 인터넷 불필요 (설치 후) |

## 설치 단계

### 1. 프로젝트 다운로드

```bash
git clone https://github.com/world970511/DataBridge_V0.git
cd DataBridge_V0
```

### 2. 환경 설정

```bash
cp .env.example .env
vi .env
```

**반드시 변경해야 하는 항목:**

```bash
# 감시할 공유 폴더 경로 (호스트 경로)
WATCH_DIR_HOST=/mnt/shared/data        # Linux
# WATCH_DIR_HOST=C:/SharedData         # Windows (백슬래시 대신 슬래시)

# DB 비밀번호 (12자 이상, 특수문자 포함 권장)
POSTGRES_PASSWORD=강력한비밀번호

# 관리자 초기 비밀번호
ADMIN_PASSWORD=관리자비밀번호

# 세션 암호화 키 (openssl rand -hex 32 로 생성)
SECRET_KEY=랜덤문자열

# Webhook 인증 토큰 (openssl rand -hex 16 으로 생성)
WEBHOOK_SECRET=랜덤문자열
```

### 3. AI 모델 설정

### 4. Docker 실행

```bash
docker compose up -d
```

실행되는 컨테이너 3개:

| 컨테이너 | 포트 | 역할 |
|---|---|---|
| `databridge-app` | 8501 | 앱 (UI + 에이전트 + 파일 감시) |
| `databridge-postgres` | 5432 | PostgreSQL |
| `databridge-chromadb` | 8000 | ChromaDB (벡터 검색) |

```
웹 브라우저에서 http://서버IP:8501
```

- 로그인 화면이 나타나면 성공
- ID: `admin` / 비밀번호: `.env`의 `ADMIN_PASSWORD`

## 동작 확인

1. 공유 폴더(`WATCH_DIR_HOST`)에 아무 엑셀/CSV 파일을 넣어보세요
2. 채팅에서 `"방금 올린 파일 내용 보여줘"` 라고 물어보세요
3. 파일이 자동으로 DB에 적재되고, 채팅으로 조회되면 정상입니다

> 💡 처리 상태는 채팅에서 `"최근 등록된 파일 목록"` 으로 확인할 수 있습니다.

## Ollama 자동 시작 설정

### Linux (systemd)

```bash
# scripts/ollama.service 파일 복사
sudo cp scripts/ollama.service /etc/systemd/system/
sudo systemctl enable ollama
sudo systemctl start ollama
```

### Windows

- **방법 1**: 시작 프로그램에 `ollama serve` 등록
- **방법 2**: 작업 스케줄러에서 부팅 시 실행 설정

## Docker 볼륨

`docker-compose.yml`에 정의된 영구 볼륨:

| 볼륨 | 용도 |
|---|---|
| `postgres_data` | PostgreSQL 데이터 |
| `chroma_data` | ChromaDB 벡터 데이터 |
| `app_logs` | 애플리케이션 로그 |
| `app_thumbnails` | 이미지 썸네일 |
| `torch_cache` | DINOv2 모델 캐시 (최초 실행 시 다운로드) |

> 공유 폴더는 `:ro` (읽기 전용)로 마운트됩니다. DataBridge가 원본 파일을 수정하지 않습니다.

## 트러블슈팅

### Ollama 연결 실패

```
Connection refused: http://host.docker.internal:11434
```

**원인**: Docker 컨테이너에서 호스트의 Ollama에 접근하지 못하는 경우

**해결**:
1. Ollama가 실행 중인지 확인: `ollama list`
2. Ollama가 모든 인터페이스에서 리스닝하는지 확인:
   ```bash
   OLLAMA_HOST=0.0.0.0 ollama serve
   ```
3. Linux Docker Engine 사용 시 `docker-compose.yml`의 `extra_hosts` 설정 확인:
   ```yaml
   extra_hosts:
     - "host.docker.internal:host-gateway"
   ```

### Docker 메모리 부족

**증상**: 앱 컨테이너가 반복적으로 재시작됨

**해결**:
- Docker Desktop: Settings → Resources → Memory를 8GB 이상으로 설정
- 이미지 처리(DINOv2) 사용 시 12GB 이상 권장
- DINOv2 모델은 최초 실행 시 자동 다운로드됨 (`torch_cache` 볼륨에 캐시)

### ChromaDB 연결 실패

```
Could not connect to ChromaDB at chromadb:8000
```

**해결**:
1. `docker compose ps`로 chromadb 컨테이너 상태 확인
2. `docker compose logs chromadb`로 로그 확인
3. 포트 충돌 시 `.env`의 `CHROMA_PORT` 변경

### CPU 환경에서 LLM 응답이 너무 느림

- `.env`의 `LLM_TIMEOUT=300` → CPU 환경에서는 자동으로 최소 600초 적용됨
- 경량 모델(`gemma2:2b`) 사용 권장
- 또는 상용 모델(OpenAI 등) 사용 고려
